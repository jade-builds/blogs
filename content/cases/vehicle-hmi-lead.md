## 제가 만든 것은 화면이면서, 다른 개발자가 구현할 기반이었습니다

MDS테크에서 현대자동차의 세로형 내비게이션 GUI 데모 개발과 개발파트 PL을 병행했습니다. 개발 4명·디자인 2명이 참여했고, 제 기여도는 50%입니다. 차량용 HMI 개발 솔루션인 EB Guide를 사용했습니다.

클러스터·홈 화면을 직접 개발하는 한편, 업무별 공통 인터페이스와 사용자 입력 이벤트도 구현했습니다. 화면을 완성하는 일과 함께, 여러 개발자가 같은 기반 위에서 기능을 나눠 만들 수 있도록 하는 일이 제 담당 범위였습니다.

## 화면에 앞서 입력과 공통 인터페이스를 다뤘습니다

원 클릭·더블 클릭·롱 터치·상하좌우 드래그의 입력 패턴을 정의하고, 패턴별 이벤트 핸들러를 개발했습니다. 클러스터·미디어 등 업무별 공통 인터페이스를 만들고, 클러스터와 홈 화면, 아이콘 드래그·이동·자동 정렬 기능을 구현했습니다.

이 작업을 화면 목록만으로 설명하면 입력을 해석하는 부분과 각 화면의 업무 동작을 연결한 경험이 빠집니다. **같은 사용자 입력이 어떤 이벤트가 되고, 화면에서 어떤 기능으로 이어지는지**를 함께 다뤘습니다.

```text
담당 책임의 개념도

사용자 입력 패턴
    → 입력 패턴별 이벤트 핸들러
    → 업무별 공통 인터페이스·화면 기능
    → 클러스터·홈·아이콘 이동 및 정렬
```

위 그림은 역할을 요약한 개념도입니다. 실제 런타임 호출 순서나 당시 상태 머신의 코드·타이밍을 재현한 것은 아닙니다.

## 직접 구현한 기반을 다른 개발자가 사용할 수 있게 했습니다

협력업체 개발자 3명에게 솔루션 사용법과 개발 교육을 진행했습니다. 프로젝트 분석·설계와 업무 할당, 일정 산정·관리를 함께 맡았고 인원별 역량에 따라 업무를 재분배했습니다.

직접 만든 기능이 있다는 것과, 팀이 그 기반을 사용해 담당 화면을 개발할 수 있다는 것은 다른 결과였습니다. 공통 구조의 구현과 솔루션 교육, 업무 배분을 함께 수행한 점이 개발파트 PL 경험의 중요한 부분입니다.

| 개발자로 수행한 일 | 개발파트 PL로 연결한 일 |
|---|---|
| 공통 인터페이스·입력 이벤트 구현 | 개발자들이 사용할 기반과 개발 방법 전달 |
| 클러스터·홈 화면·아이콘 기능 개발 | 역량에 따른 업무 할당·재분배 |
| 프로젝트 구조와 업무 로직 적용 구조 설계 | 일정 산정·관리와 요구사항 조율 |

이 표는 직접 수행한 역할의 연결입니다. 교육 3명과 개발 4명·디자인 2명을 별도 인원으로 합산하지 않습니다.

## 요구사항을 구현과 일정 사이에서 조율했습니다

고객사와 디자인 업체의 요구사항을 협의하고 일정을 조율했습니다. 구현을 담당하는 개발자, 화면을 정의하는 디자인 측, 결과를 확인하는 고객사 사이에서 요구사항을 전달하고 맞추는 역할이었습니다.

다만 실제 요구 변경의 세부 사례나 회의·리뷰 제도를 임의로 덧붙이지는 않습니다. 제가 맡은 것은 개발파트의 리딩과 직접 개발이며, 전체 프로젝트의 모든 조직을 총괄했다는 의미가 아닙니다.

## 결과는 데모 구현과 일정 내 완료였습니다

공통 인터페이스·입력 이벤트·클러스터·홈 화면·아이콘 동작을 개발하고, 협력업체 교육과 업무 배분·일정 조율을 병행해 일정 내 프로젝트를 완료했습니다. 이 결과는 **내비게이션 GUI 데모**의 범위입니다. 양산 차량 탑재, 안전 인증이나 실제 도로 운행 검증을 완료했다는 뜻은 아닙니다.

이 경험은 이후 공통파트 PL 역할에서도 이어졌습니다. 기능을 직접 만드는 것에 더해, 다른 개발자가 사용할 수 있는 기반과 수행 조건을 정리하는 일이 필요하다는 기준입니다. 기술 스택은 달라졌지만 구현과 협업의 경계를 함께 다룬 경험으로 남았습니다.
